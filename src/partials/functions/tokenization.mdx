## Tokenization

### What this does
Stores a card on file and returns a token that can be used for future transactions without requiring the card to be present again.

### When to use it
Use for subscription billing, recurring payments, or "save my card" flows. The token replaces the PAN — your system never stores raw card data.

### Implementation notes

1. The token is acquirer-specific and non-portable — a token from TSYS cannot be used with another acquirer.
2. Three flows are available: **tokenize-only** (card is read, token returned, no charge), **sale-and-tokenize** (card is charged and tokenized in one step), and **deferred tokenization** (token retrieved from a previously completed transaction where tokenization was not enabled at the time).
3. Tokens do not expire unless the underlying card expires or the cardholder requests deletion.
4. For future charges using the token, use the Cloud API `/moto/sale` endpoint with the token in place of card details.
5. **Deferred tokenization** (Android SDK 7.1013.1+): `hapi.deferredTokenization(eftTransactionID)` sends a command to the connected PAX device to retrieve the token for a prior transaction. The `eftTransactionID` is the `EFTTransactionID` (UUID) from the original transaction result — not `transactionID` (the internal card-reader number). Result arrives via `endOfTransaction`.
6. **Deferred tokenization** (Cloud API): `GET /transactions/{transactionID}/token` retrieves a token server-side — no terminal required. Eligible transaction types: `sale`, `refund`, `preAuthorizationCapture`, `moToSale`, `moToRefund`.

```kotlin

val sent: Boolean = hapi.deferredTokenization("01236fc0-8192-11eb-9aca-ad4b0e95f241")

// Token arrives via endOfTransaction:
override fun endOfTransaction(result: TransactionResult, device: Device) {
    val token = result.cardToken  // store and use in hapi.motoSale() with MoToOptions
}
```

### Parameters

**Card-present tokenization** (`tokenizeCard` / `saleAndTokenizeCard`):

| Name | Type | Required | Description |
|---|---|---|---|
| `operation` | string | Yes (Cloud API) | `"tokenizeCard"` for tokenize-only, `"saleAndTokenizeCard"` for sale+tokenize |
| `amount` | string | Yes (saleAndTokenizeCard) | Amount in smallest currency unit as a string |
| `currency` | string | Yes (saleAndTokenizeCard) | ISO 4217 currency code |
| `serial_number` | string | Yes (Cloud API) | Target terminal serial number |
| `terminal_type` | string | Yes (Cloud API) | Terminal model, e.g. `"PAXA920"` |

**Deferred tokenization** — `hapi.deferredTokenization(originalTransactionID)` (Android SDK 7.1013.1+):

| Parameter | Type | Description |
|---|---|---|
| `originalTransactionID` | `String` | `EFTTransactionID` (UUID) from the original transaction result — NOT `transactionID` (the internal device number) |
| `options` | `Options?` | Optional — supports `customerReference` |
| **Returns** | `Boolean` | `true` if the command was sent to the device; `false` if not (device not connected or command failed to send). The tokenization result arrives via `endOfTransaction`. |

**Deferred tokenization** — Cloud API (`GET /transactions/{transactionID}/token`):

| Parameter | Description |
|---|---|
| `{transactionID}` | The `transactionID` (GUID) from the original card-present transaction |

### Response fields

| Field | Description |
|---|---|
| `cardToken` | The token to store. Use for future charges via `/moto/sale` |
| `cardTokenProvider` | Which token provider issued the token (e.g. `TSYS`, `PAYSAFE`) |
| `expiryDateMMYY` | Token expiry (matches card expiry) |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `TOKENIZATION_NOT_ENABLED` | Not configured for this merchant | Contact Handpoint team |
| `CARD_READ_ERROR` | Terminal failed to read card | Retry; ask customer to try again |

### Testing
Tokenization on the TEST/DEMO merchant or staging device returns a test token. Test tokens are not valid in the production environment.
