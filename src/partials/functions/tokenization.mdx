## Tokenization

### What this does
Stores a card on file and returns a token that can be used for future transactions without requiring the card to be present again.

### When to use it
Use for subscription billing, recurring payments, or "save my card" flows. The token replaces the PAN — your system never stores raw card data.

### Implementation notes

1. The token is acquirer-specific and non-portable — a token from TSYS cannot be used with another acquirer.
2. Two flows are available: **tokenize-only** (card is read, token returned, no charge) and **sale-and-tokenize** (card is charged and tokenized in one step).
3. Tokens do not expire unless the underlying card expires or the cardholder requests deletion.
4. For future charges using the token, use the Cloud API `/moto/sale` endpoint with the token in place of card details.
5. You can also retrieve a token from a previously completed transaction (within 12 months) via `GET /transactions/{transactionID}/token`.

### Parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `operation` | string | Yes (Cloud API) | `"tokenizeCard"` for tokenize-only, `"saleAndTokenizeCard"` for sale+tokenize |
| `amount` | string | Yes (saleAndTokenizeCard) | Amount in smallest currency unit as a string |
| `currency` | string | Yes (saleAndTokenizeCard) | ISO 4217 currency code |
| `serial_number` | string | Yes (Cloud API) | Target terminal serial number |
| `terminal_type` | string | Yes (Cloud API) | Terminal model, e.g. `"PAXA920"` |

### Response fields

| Field | Description |
|---|---|
| `cardToken` | The token to store. Use for future charges via `/moto/sale` |
| `cardTokenProvider` | Which token provider issued the token (e.g. `TSYS`, `PAYSAFE`) |
| `expiryDateMMYY` | Token expiry (matches card expiry) |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `TOKENIZATION_NOT_ENABLED` | Not configured for this merchant | Contact Handpoint team |
| `CARD_READ_ERROR` | Terminal failed to read card | Retry; ask customer to try again |

### Testing
Tokenization on the TEST/DEMO merchant or staging device returns a test token. Test tokens are not valid in the production environment.
