## Card PAN

### What this does
Prompts the cardholder to tap or insert their card, reads the card data (PAN, expiry, card scheme), and returns it without processing a payment. No transaction is created.

### When to use it
Use for enrollment flows where you need to associate a card with an account before the first transaction — for example, registering a loyalty card or creating an on-file payment method. The PAN returned is the raw PAN from the chip or magnetic stripe, **not a token**. Handle and store it only if your system is PCI-DSS compliant. For most use cases, use Tokenization instead to receive a safe card token.

:::caution PCI scope
`cardPan()` returns the unmasked PAN. Your system becomes PCI in-scope if you store or transmit it. Use [Tokenization](/functions/tokenization) instead unless you have a specific need for the raw PAN and are operating within a PCI-compliant environment.
:::

### Implementation notes

1. The cardholder taps or inserts their card at the terminal — chip and contactless are both supported.
2. The result arrives in the `endOfTransaction` callback. Check `result.unMaskedPan` for the full PAN.
3. This is a PAX-only operation — HiLite does not support standalone card read without a transaction.

```kotlin
hapi.cardPan()

override fun endOfTransaction(result: TransactionResult, device: Device) {
    if (result.finStatus == FinancialStatus.AUTHORISED) {
        val pan = result.unMaskedPan     // full PAN — handle within PCI scope
        val expiry = result.expiryDateMMYY
        val scheme = result.cardSchemeName
    }
}
```

### Parameters

`cardPan()` takes no required parameters. An optional `Options` object can be passed to override connection or merchant configuration.
