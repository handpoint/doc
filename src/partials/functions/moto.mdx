## MOTO (Mail Order / Telephone Order)

### What this does
Processes a card-not-present transaction where the cardholder provides card details by phone or mail. The card is never physically read — a stored card token is used instead.

### Two MOTO modes

| Mode | How it works | Terminal required | Who holds card data |
|---|---|---|---|
| **MOTO on terminal** | REST API commands the PAX terminal to display a manual card entry screen. The operator types card details on the terminal. Terminal tokenizes and sends. | ✅ PAX in integrated mode | Handpoint terminal |
| **MOTO back-office** | A `cardToken` from a supported token provider is sent via REST API or Android SDK. No terminal or card entry required. | ❌ None | Token provider (never the ISV) |

:::info No raw card data
Handpoint MOTO does not accept raw PAN, expiry, or CVV from the ISV system. All MOTO operations use a `cardToken` issued by a supported token provider (e.g. TSYS, Paysafe, Tokenex). The token provider de-tokenizes to PAN + expiry when processing the transaction — the ISV system never handles raw card data.
:::

### When to use it
Use for call centres, phone order systems, or recurring billing where the cardholder previously consented to card-on-file. A card token must exist before a MOTO transaction can be processed — tokens are obtained via the [Tokenization](/acquirers/tsys#tokenization) operation on the original card-present or online transaction.

### Implementation notes

1. The card token must come from a token provider supported by the merchant's acquirer.
2. Some acquirers restrict MOTO to specific merchant category codes (MCCs) — confirm with your acquirer.
3. **MOTO on terminal**: the PAX device must be running the Android SDK in integrated mode. The terminal entry screen collects card details and tokenizes internally.
4. **MOTO back-office**: the `cardToken` is passed directly in the API request. No terminal required.

### Parameters

**MOTO on terminal** (terminal serial number, no card token):

| Name | Type | Required | Description |
|---|---|---|---|
| `amount` | integer | Yes | Amount in smallest currency unit |
| `currency` | string | Yes | ISO 4217 currency code |
| `motoChannel` | boolean | Yes | Must be `true` |
| `terminal_serial_number` | string | Yes | PAX terminal — triggers card entry screen |

**MOTO back-office** (card token, no terminal):

| Name | Type | Required | Description |
|---|---|---|---|
| `amount` | integer | Yes | Amount in smallest currency unit |
| `currency` | string | Yes | ISO 4217 currency code |
| `motoChannel` | boolean | Yes | Must be `true` |
| `cardToken` | string | Yes | Token from a supported token provider. Never a raw PAN. |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `DECLINED` | Issuer declined | Ask customer for another card or token |
| `INVALID_TOKEN` | Card token not recognised | Verify token and token provider match the acquirer |
| `MOTO_NOT_ENABLED` | MOTO not enabled for this merchant | Contact Handpoint team |

### Testing
Test MOTO on terminal using a PAX debug device on staging. Test MOTO back-office using a valid card token from a staging tokenization — see [Tokenization](/acquirers/tsys#tokenization).
