## MOTO (Mail Order / Telephone Order)

### What this does
Processes a card-not-present transaction where the cardholder provides card details by phone or mail.

### Two MOTO modes

MOTO is available in two distinct modes — both use the REST API but differ in how card data is captured:

| Mode | How it works | Terminal required | PCI scope |
|---|---|---|---|
| **MOTO on terminal** | REST API commands the PAX terminal to display a manual card entry screen. The operator types card details on the terminal. | ✅ PAX in integrated mode | Lower — card data stays on terminal |
| **MOTO back-office** | REST API request body contains raw card data (PAN, expiry, CVV). No terminal involved. | ❌ None | Higher — ISV system handles card data |

:::caution PCI DSS
MOTO back-office mode requires your system to handle raw card data. Ensure your platform is PCI DSS compliant before using this mode. MOTO on terminal keeps card data on the Handpoint terminal and reduces your PCI scope.
:::

### When to use it
Use for call centres, phone order systems, or any flow where the cardholder is not physically present. Do NOT use for card-present transactions — always use Sale for in-person payments.

### Implementation notes

1. Some acquirers restrict MOTO to specific merchant category codes (MCCs) — confirm with your acquirer.
2. MOTO transactions carry higher fraud risk and interchange rates than card-present transactions.
3. For **MOTO on terminal**: the PAX device must be running the Android SDK in integrated mode and connected to the Handpoint Cloud.
4. For **MOTO back-office**: no terminal required — see the [Back Office section](/back-office/rest-api-no-reader).

### Parameters

**MOTO on terminal** (`terminal_serial_number` present, no `card` object):

| Name | Type | Required | Description |
|---|---|---|---|
| `amount` | integer | Yes | Amount in smallest currency unit |
| `currency` | string | Yes | ISO 4217 currency code |
| `motoChannel` | boolean | Yes | Must be `true` |
| `terminal_serial_number` | string | Yes | PAX terminal serial number — triggers on-terminal card entry screen |

**MOTO back-office** (`card` object present, no `terminal_serial_number`):

| Name | Type | Required | Description |
|---|---|---|---|
| `amount` | integer | Yes | Amount in smallest currency unit |
| `currency` | string | Yes | ISO 4217 currency code |
| `motoChannel` | boolean | Yes | Must be `true` |
| `card.number` | string | Yes | Card PAN (no spaces) |
| `card.expiryDate` | string | Yes | `MMYY` format |
| `card.cvv` | string | Yes | Card verification value |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `DECLINED` | Issuer declined | Ask customer for another card |
| `INVALID_CARD_NUMBER` | Card number failed Luhn check | Verify number with customer |
| `CVV_MISMATCH` | CVV does not match | Re-confirm with customer |
| `MOTO_NOT_ENABLED` | MOTO not enabled for this merchant | Contact Handpoint team |

### Testing
Test MOTO on terminal using a PAX debug device on staging. Test MOTO back-office using a REST API call without a terminal serial number against the staging environment.
