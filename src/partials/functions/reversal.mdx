## Reversal

### What this does
Voids a transaction before settlement, returning the full authorised amount to the cardholder without incurring interchange fees.

### When to use it
Use when a transaction needs to be cancelled before the batch closes (same business day, before cut-off time). This is always preferable to a refund for same-day cancellations — faster and fee-free. **No card present required** — reversal is sent electronically using the original transaction reference. Do NOT use after settlement — send a Refund instead.

### Implementation notes

1. **Same business day only.** Reversal works on the current open batch only. Once the batch closes (cut-off time, typically end of business day), the transaction settles and only a post-settlement Refund is available.
2. **No card present required.** Reversal is an electronic operation referencing the original `transactionID`. The cardholder does not need to return to the terminal.
3. **Three paths — different connectivity requirements and response shapes:**
   - **Cloud API with reader** (`POST /transactions`): routes the reversal through the connected terminal. Terminal must be online. Asynchronous — poll `GET /transaction-result/{id}` for the result. Amount in minor units.
   - **Cloud API without reader** (`POST /reversal`): sent directly to the gateway. Works for **any transaction type** (sale, refund, pre-auth, MOTO, etc.). Terminal does not need to be connected. **Synchronous** — result is in the response body. Amount in major units (decimal string). Different response schema from the standard transaction result. Include `amount` and `currency` for partial reversals on merchants that support it — omit for a full reversal.
   - **Android SDK / iOS SDK**: reversal travels through the connected reader. The terminal must be reachable at the time of the call.
5. For Interac card transactions (TNS / TSYS + TNS): the only post-sale operation available is VOID (card must be present). Show a VOID button, not Refund or Reverse, for Interac transactions in your UI.

### Parameters

**Cloud API with reader** — `POST /transactions`:

| Name | Type | Required | Description |
|---|---|---|---|
| `operation` | string | Yes | Must be `"saleReversal"` |
| `amount` | string | Yes | Full original sale amount in **minor units** as a string, e.g. `"1100"` = $11.00 |
| `currency` | string | Yes | ISO 4217 currency code — must match the original sale |
| `terminal_type` | string | Yes | Terminal model, e.g. `"PAXA920"` |
| `serial_number` | string | Yes | Terminal serial number |
| `originalTransactionId` | string | Yes | `transactionID` from the original sale result |

**Cloud API without reader** — `POST /reversal`:

| Name | Type | Required | Description |
|---|---|---|---|
| `originalGuid` | string | Yes | `transactionID` from the original transaction (any type) |
| `amount` | string | No | Amount to reverse in **major units** as a decimal string, e.g. `"12.00"`. Omit for a full reversal. Required for partial reversals on merchants that support it |
| `currency` | string | No | ISO 4217 currency code. Required when `amount` is provided |

**Android SDK / iOS SDK** — reversal sent through the connected reader:

| Name | Type | Description |
|---|---|---|
| `amount` | `BigInteger` | Full original sale amount in minor currency units |
| `currency` | `Currency` | Currency of the original sale |
| `originalTransactionID` | `String` | `transactionID` from the original sale result |

### Errors

**Cloud API with reader** — errors arrive in the polled result object, not in the initial 202 response. Check `finStatus` — do not parse `statusMessage` for programmatic logic as it can be localized.

| `finStatus` | `statusMessage` | Meaning | What to do |
|---|---|---|---|
| `DECLINED` | `UNABLE_TO_FIND_MESSAGE_TO_REVERSE.` | `originalTransactionId` not found in the open batch | Verify the GUID; if the batch has closed, send a Refund instead |
| `DECLINED` | `PARTIAL_REVERSAL_AMOUNT_EXCEEDS_ORIGINAL_AMOUNT` | Reversal amount is greater than original sale | Use the exact original amount — partial reductions of the reversed amount are not supported here |
| `FAILED` | `Transaction failed, error: Error getting advanced transaction status (transaction not found)...` | `originalTransactionId` not found (pre-auth reversal path) | Verify the GUID is the `transactionID` from the pre-auth create result |

**Cloud API with reader** — immediate HTTP errors (returned before the 202):

| HTTP | `message` | Meaning | What to do |
|---|---|---|---|
| `403` | `No valid key found in header` | Missing or invalid API key | Check `ApiKeyCLoud` header value |
| `400` | `{"error":1001,"message":"Device is busy"}` | Terminal is processing another operation | Wait and retry; implement a short backoff |
| `400` | `TransactionReference with wrong uuidv4 format ...` | `transactionReference` is not a valid UUID v4 | Generate a compliant UUID v4 (version digit must be `4`, variant digit `8`/`9`/`a`/`b`) |

**Cloud API without reader (`POST /reversal`)** — synchronous, errors are immediate:

| HTTP | `code` | `message` | Meaning | What to do |
|---|---|---|---|---|
| `400` | `3153` | `Unable to find message to reverse.` | `originalGuid` not found | Verify the GUID is the `transactionID` from the original transaction result |
| `400` | `3051` | `Already reversed` | Transaction has already been reversed | No further action needed; check your records |
| `400` | `4066` | `Partial reversal amount exceeds original amount` | `amount` exceeds the original transaction amount | Reduce the amount to at most the original; omit `amount` entirely for a full reversal |

### Testing

Test reversals on the TEST/DEMO merchant or staging device. The most important edge case is cut-off timing.
