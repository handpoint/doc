## Reversal

### What this does
Voids a sale before settlement, returning the full authorised amount to the cardholder without incurring interchange fees.

### When to use it
Use when a sale needs to be cancelled before the batch closes (same business day, before cut-off time). This is always preferable to a refund for same-day cancellations — faster and fee-free. **No card present required** — reversal is sent electronically using the original transaction reference. Do NOT use after settlement — send a Refund instead.

### Implementation notes

1. **Same business day only.** Reversal works on the current open batch only. Once the batch closes (cut-off time, typically end of business day), the transaction settles and only a post-settlement Refund is available.
2. **No card present required.** Reversal is an electronic operation referencing the original `transactionID`. The cardholder does not need to return to the terminal.
3. Full amount only — partial reversals are a separate operation (`partial-reversal`), supported only on TSYS US.
4. **Two paths — different terminal requirements:**
   - **REST API (Cloud API / back-office):** reversal is sent directly to the gateway. The terminal does not need to be online or connected.
   - **Android SDK / iOS SDK:** reversal travels through the connected reader. The original terminal must be reachable over Bluetooth or the local network at the time of the call.
5. For Interac card transactions (TNS / TSYS + TNS): the only post-sale operation available is VOID (card must be present). Show a VOID button, not Refund or Reverse, for Interac transactions in your UI.

### Code

<Tabs groupId="integration-path">
<TabItem value="cloud-api" label="Cloud API">

The reversal is sent **directly to the gateway** — the terminal does not need to be online or connected.

```http
POST https://cloud.handpoint.com/transactions
ApiKeyCloud: YOUR_MERCHANT_API_KEY
Content-Type: application/json

{
  "operation": "saleReversal",
  "amount": "1000",
  "currency": "USD",
  "originalTransactionId": "01236fc0-8192-11eb-9aca-ad4b0e95f241"
}
```

`originalTransactionId` is the `transactionID` from the original sale result. `amount` and `currency` must match the original sale. Do not include a `transactionReference` — this is a subsequent operation linked to the original sale's reference.

### Parameters

**Cloud API** — `POST /transactions` (direct gateway call, no terminal required):

| Name | Type | Required | Description |
|---|---|---|---|
| `operation` | string | Yes | Must be `"saleReversal"` |
| `amount` | string | Yes | Full original sale amount in smallest currency unit as a string |
| `currency` | string | Yes | ISO 4217 currency code — must match the original sale |
| `originalTransactionId` | string | Yes | `transactionID` from the original sale result |

**Android SDK / iOS SDK** — reversal sent through the connected reader:

| Name | Type | Description |
|---|---|---|
| `amount` | `BigInteger` | Full original sale amount in minor currency units |
| `currency` | `Currency` | Currency of the original sale |
| `originalTransactionID` | `String` | `transactionID` from the original sale result |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `ORIGINAL_NOT_FOUND` | Reference not found or batch already closed | Send a Refund instead |
| `ALREADY_REVERSED` | Transaction already reversed | No action needed |
| `TIMEOUT` | Terminal did not respond | Check connection; retry |

### Testing

Test reversals on the TEST/DEMO merchant or staging device. The most important edge case is cut-off timing.

<Tabs groupId="integration-path">
<TabItem value="cloud-api" label="Cloud API">

| Scenario | How to trigger |
|---|---|
| Before cut-off (success) | Complete a sale, send reversal same day — verify `AUTHORISED` with no card prompt |
| After cut-off (failure) | Close the batch manually, then attempt reversal — verify `ORIGINAL_NOT_FOUND` and that your UI routes to Refund |
| Already reversed | Send the same reversal twice — verify idempotent response on second call |
