### Pre-Authorization Increase / Decrease

Adjusts the held amount on an open pre-authorization before capture.

**When to use:** When the expected final charge has changed after the initial hold was placed — for example, a hotel stay is extended (increase) or a car rental is returned early (decrease). Send before capture.

**Implementation notes:**
1. The `amount` is the **delta** — the amount to add to (or subtract from) the current hold, not the new total. To raise a $100 hold to $120, send a delta of $20. To lower it to $80, send a delta of $20 with a decrease signal.
2. The decrease mechanism differs by integration path — see the code tab for your path.
3. Increase above the original amount is subject to acquirer and issuer limits. Check the acquirer capabilities matrix.
4. The `originalTransactionID` must be the `transactionID` from the pre-auth create result.

<TabItem value="cloud-api" label="Cloud API">

**With reader** — routes through the terminal (`POST /transactions`). Amount in **minor units**; use a **negative** amount to decrease.

```http
POST https://cloud.handpoint.com/transactions
ApiKeyCloud: YOUR_MERCHANT_API_KEY
Content-Type: application/json

{
  "operation": "preAuthorizationIncrease",
  "amount": "2000",
  "currency": "USD",
  "terminal_type": "PAXA920",
  "serial_number": "082104578",
  "originalTransactionId": "01236fc0-8192-11eb-9aca-ad4b0e95f241"
}
```

To decrease, pass a negative `amount`: `"amount": "-2000"`.

**Without reader** — sent directly to the gateway (`POST /preauthorization/increase`). Amount in **major units** (decimal); use `subtract: "1"` to decrease.

```http
POST https://cloud.handpoint.com/preauthorization/increase
ApiKeyCloud: YOUR_MERCHANT_API_KEY
Content-Type: application/json

{
  "originalGuid": "01236fc0-8192-11eb-9aca-ad4b0e95f241",
  "increaseAmount": "20.00"
}
```

To decrease, add `"subtract": "1"` to the body.

**Cloud API with reader** — `POST /transactions`:

| Parameter | Type | Required | Description |
|---|---|---|---|
| `operation` | string | Yes | Must be `"preAuthorizationIncrease"` |
| `amount` | string | Yes | Delta in **minor units** as a string. Use a negative value to decrease, e.g. `"-2000"` |
| `currency` | string | Yes | ISO 4217 currency code |
| `terminal_type` | string | Yes | Terminal model, e.g. `"PAXA920"` |
| `serial_number` | string | Yes | Terminal serial number |
| `originalTransactionId` | string | Yes | `transactionID` from the pre-auth create result |

**Cloud API without reader** — `POST /preauthorization/increase`:

| Parameter | Type | Required | Description |
|---|---|---|---|
| `originalGuid` | string | Yes | `transactionID` from the pre-auth create result |
| `increaseAmount` | string | Yes | Delta in **major units** as a decimal string, e.g. `"20.00"` — always positive |
| `subtract` | string | No | Pass `"1"` to subtract the delta (decrease) instead of adding it |
| `tipAmount` | string | No | Tip amount in major units as a decimal string, e.g. `"2.00"` |
| `customerReference` | string | No | Integrator-defined reference forwarded as-is to the gateway |

**Android SDK** — `preAuthorizationIncrease(amount, currency, originalTransactionID, options?)`:

| Parameter | Type | Description |
|---|---|---|
| `amount` | `BigInteger` | Delta in minor currency units. Pass a **negative** value to decrease |
| `currency` | `Currency` | Currency of the original pre-authorization |
| `originalTransactionID` | `String` | `transactionID` from the pre-auth create result |
| `options` | `Options?` | Optional — supports `customerReference` |

### Errors

**Cloud API without reader (`POST /preauthorization/increase`)** — synchronous:

| HTTP | `code` | `message` | Meaning | What to do |
|---|---|---|---|---|
| `400` | `5001` | `NullPointerException` | `originalGuid` not found | Verify the GUID is the `transactionID` from the pre-auth create result |
| `400` | `3211` | *(pre-auth already settled)* | Pre-auth has already been captured or voided | Check transaction state before adjusting |
| `403` | — | `No valid key found in header` | Invalid API key | Check `ApiKeyCLoud` header |
| `422` | `VALIDATION_FAILED` | Missing or wrong field name | The required field is `increaseAmount`, not `amount` | See `details` array in response for the specific missing property |

:::note
The no-reader endpoint (`POST /preauthorization/increase`) requires `increaseAmount` (always positive) with an optional `subtract: "1"` for decrease. The with-reader endpoint (`POST /transactions`) uses a negative `amount` for decrease — there is no `subtract` field on that path.
:::

<TabItem value="cloud-api" label="Cloud API">

| Scenario | How to trigger |
|---|---|
| Increase (no reader) | Create pre-auth → `POST /preauthorization/increase` with `increaseAmount` delta — verify new hold amount |
| Decrease (no reader) | Same endpoint, add `"subtract": "1"` — verify reduced hold |
| Increase (with reader) | `POST /transactions` with `operation: "preAuthorizationIncrease"` and positive `amount` — terminal must be online |
| Decrease (with reader) | Same, but `amount` is negative, e.g. `"-2000"` |
| Capture after adjustment | Increase/decrease → capture — verify settled amount matches adjusted total |
