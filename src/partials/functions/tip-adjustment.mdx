## Tip Adjustment

### What this does
Modifies the tip amount on a completed sale before batch close.

### When to use it
Use in restaurant/hospitality flows where the cardholder adds a tip after the initial transaction is approved. Do NOT use after batch close — send a Refund for the difference instead.

### Implementation notes

1. **Last adjustment wins.** Each call replaces the previous tip value — there is no accumulation. If the cardholder adds $2 and then changes it to $5, send $5 as the full tip. To void a tip that was already set, send `amount: 0`.
2. **Deadline: before batch close.** The cut-off time is determined by your acquirer and the merchant's onboarding configuration, not by a fixed clock time. Contact your Handpoint integration engineer for the exact cut-off for your merchant. After close, the transaction has settled and only a post-settlement Refund is possible.
3. **Acquirer-specific restriction — TSYS:** tip adjustment is only available on transactions where **no tip was collected on-screen during the original sale** (tip-at-table flow). If the original sale included an on-screen tip prompt, TSYS will reject the tip adjustment. For TSYS merchants using on-screen tips, use tip adjustment only when the sale was processed without a tip prompt.
4. **No card required.** The terminal must be connected and idle. The cardholder does not need to be present.
5. **Math:** the cardholder is charged `original_sale_amount + tip_amount` at settlement. Tip adjustment does not replace the original transaction amount.
6. **Back-office path works cross-SDK:** a sale made via Android SDK can have its tip adjusted via Cloud API. The integration path used for the sale does not constrain the tip adjustment path.
7. **`tipAdjustment()` is synchronous on the Android SDK** — it returns a `Boolean` directly. There is no `endOfTransaction` callback for this operation. `true` = adjustment accepted by the gateway; `false` = rejected. Check the return value immediately after the call.
8. **TMS enablement** is set during onboarding by the Handpoint team. Integrators cannot check or enable this via API — contact your Handpoint integration engineer.
9. iOS HiLite does not support card-present tip adjustment. Use Cloud API.

### Parameters

**Cloud API** — `POST /transactions/{transactionID}/tip-adjustment`:

| Name | Type | Required | Description |
|---|---|---|---|
| `{transactionID}` | string (path) | Yes | `transactionID` from the original sale result |
| `amount` | number | Yes | Tip amount in major currency units (e.g. `9.00` for $9.00). `0` to void an existing tip |

**Android SDK** — `tipAdjustment(tipAmount, currency, originalTransactionID)`:

| Parameter | Type | Description |
|---|---|---|
| `tipAmount` | `BigInteger` | Tip amount in minor units. `BigInteger("0")` to void |
| `currency` | `Currency` | Currency of the original transaction |
| `originalTransactionID` | `String` | `transactionID` from the original sale result |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `ORIGINAL_NOT_FOUND` | Transaction ID not found | Verify the ID |
| `BATCH_ALREADY_CLOSED` | Batch has closed | Refund the tip amount instead |
| `TIP_ADJUSTMENT_NOT_ENABLED` | TMS config not set | Contact Handpoint onboarding team |
| `AMOUNT_EXCEEDS_LIMIT` | Tip exceeds allowed percentage | Verify tip amount |
