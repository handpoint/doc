Commands a PAX terminal to display a **manual card entry screen** — the cashier types the cardholder's card number, expiry, and CVV directly on the terminal's touchscreen. The terminal tokenizes the entry internally and processes it as a MOTO transaction. The ISV system never handles raw card data.

#### When to use it
Use for phone orders where the cardholder reads their card details aloud to a call centre agent, or in-person situations where the card cannot be read electronically. The PAX terminal must be present in your environment and running in integrated mode.

:::info Card data stays on the terminal
Unlike back-office MOTO (which uses a stored card token), key entry sale requires the PAX terminal to be physically present. The operator's system sends the command; the terminal's screen collects the card details.
:::

#### Parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `operation` | string | Yes (Cloud API) | `"moToSale"` — triggers card entry screen on terminal |
| `amount` | string | Yes | Smallest currency unit — `"1000"` = $10.00 |
| `currency` | string | Yes | ISO 4217 code |
| `serial_number` | string | Yes (Cloud API) | PAX terminal serial number |
| `terminal_type` | string | Yes (Cloud API) | Terminal model, e.g. `"PAXA920"` |
| `transactionReference` | string | No | UUID v4 for idempotency and status queries |

#### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `DECLINED` | Issuer declined | Ask cardholder to provide another card |
| `CANCELLED` | Operator cancelled on terminal | No action required |
| `MOTO_NOT_ENABLED` | MOTO not enabled for this merchant | Contact Handpoint team |
