Charge the card and simultaneously capture a **Paysafe single-use token** — a short-lived, one-time credential that lets you securely pass card data to Paysafe's Customer Vault API without your server ever handling the raw PAN.

:::caution Paysafe-ecosystem token — not for Handpoint MOTO
This token is intended for use on **Paysafe's Customer Vault API**, not Handpoint's Remote Sale (MOTO) endpoint. Handpoint Gateway does not detokenize Paysafe single-use tokens for MOTO processing.

Contact the **Paysafe team** before building a token-based flow to confirm the token format Handpoint returns meets your integration requirements.
:::

#### When to use it
Use when onboarding a customer in person — take the first payment as a normal card-present sale and simultaneously capture a Paysafe single-use token. Your system then calls the Paysafe Customer Vault API to vault the card and receive a permanent `paymentToken` for future recurring charges.

#### Result fields

| Field | Description |
|---|---|
| `cardToken` | Paysafe single-use token — pass to Paysafe Customer Vault API; **not** for Handpoint MOTO |
| `finStatus` | `AUTHORISED` on success |

#### Using the token

Pass the single-use token to Paysafe's Customer Vault API to vault the card and receive a permanent `paymentToken` for future recurring charges. The single-use token expires in ~15 minutes — vault it promptly.

For implementation details, see the [Paysafe Single-Use Token section](#paysafe-token) in Tokenization.

:::caution Token scope
Paysafe tokens are specific to the merchant configuration. Test tokens (from `api.test.paysafe.com`) are not valid in production.
:::
