## Tokenized Operation

#### What this does

**Android SDK:** Reads a card physically present at the terminal, tokenizes it, then allows you to inspect the token before deciding whether to proceed with a sale. The SDK pauses after tokenization and waits for the integrator to call `resume()` — giving you a chance to look up loyalty records, perform fraud checks, or adjust the tip before the charge goes through.

**Cloud API:** Charges a pre-stored card token server-side using `POST /moto/sale` — no terminal required. The token can come from a prior card-present tokenization or from the deferred tokenization endpoint.

:::info Two flows, one page
These two integration paths have different semantics. The Android SDK `tokenizedOperation()` requires a card-present terminal. The Cloud API token charge is server-side only — no hardware needed.
:::

#### When to use it

- **Android SDK** — loyalty programs, tiered tip flows, or any scenario where you need to inspect the token or cardholder data before committing to the charge.
- **Cloud API** — recurring billing or subscription charges against a card token obtained from a previous tokenization.

For purely storing a card without charging it, see [Tokenization](/functions/tokenization).
For MOTO back-office charges using a stored token (no terminal), see [MOTO](/functions/moto).

#### Implementation notes

1. **Android SDK two-phase flow** — `tokenizedOperation(amount, currency)` triggers Phase 1. The SDK reads the card and fires the `Events.CardTokenization.cardTokenized()` callback with a `ResumeCallback` and the card's `CardTokenizationData`. Call `callback.resume(operationDto)` to proceed with the Sale in Phase 2, or `callback.cancel()` to abort.
2. **Android SDK seamless variant** — `tokenizedOperation(currency, operation)` runs tokenization and the operation back-to-back with no pause. No `cardTokenized` event fires. Supported operations: SaleReversal, Refund, RefundReversal.
3. **`tokenizeCard()` only** — to tokenize without any follow-up operation (pure card-on-file storage), use `hapi.tokenizeCard()` from the [Tokenization](/functions/tokenization) page.
4. **Cloud API token charge** — uses `POST /moto/sale` with the `cardToken` field. The token can come from a prior `tokenizeCard`/`saleAndTokenizeCard` operation, or from a deferred tokenization call (`GET /transactions/{guid}/token`) on a transaction where tokenization was not enabled at the time. See [Tokenization](/functions/tokenization) for how to obtain a token.

```kotlin
    val tipAmount = cardTokenizationData.tipAmount  // tip collected on-screen (if any)

    // Apply business logic — loyalty lookup, fraud check, tip adjustment, etc.

    // Option A: proceed with the Sale
    callback.resume(OperationDto())

    // callback.cancel()

// Phase 2 result arrives in endOfTransaction:
override fun endOfTransaction(result: TransactionResult, device: Device) {
    if (result.finStatus == FinancialStatus.AUTHORISED) {
        // result.transactionID — store for potential reversal
        // result.cardToken — the token for future use
    }
}
```

**Seamless variant** — tokenize and execute back-to-back; no `cardTokenized` event fires:

```kotlin
// Supported operations: SaleReversal, Refund, RefundReversal
```

#### Parameters

**Cloud API** — `POST /moto/sale`:

| Parameter | Type | Required | Description |
|---|---|---|---|
| `amount` | string | Yes | Amount in **major currency units** as a decimal string, e.g. `"10.00"` for $10.00 |
| `currency` | string | Yes | ISO 4217 currency code |
| `cardToken` | string | Yes | Token from a prior `tokenizeCard`/`saleAndTokenizeCard`, or from `GET /transactions/{guid}/token` |
| `transactionReference` | string | Recommended | UUID v4 for idempotency |

**Android SDK** — `tokenizedOperation(amount, currency)` (two-phase):

| Parameter | Type | Description |
|---|---|---|
| `amount` | `BigInteger` | Sale amount in minor currency units (e.g. `BigInteger("1000")` = $10.00) |
| `currency` | `Currency` | Currency of the sale |

**`CardTokenizationData` fields** (received in the `cardTokenized` callback):

| Field | Type | Description |
|---|---|---|
| `token` | `String` | Card token — store for future charges |
| `expiryDate` | `String` | Card expiry date |
| `cardBrand` | `String` | Card brand (e.g. `"Visa"`, `"Mastercard"`) |
| `tenderType` | `TenderType` | How the card was presented (chip, contactless, etc.) |
| `tipAmount` | `BigInteger` | Tip collected on-screen (zero if no tip was collected) |
| `issuerCountryCode` | `CountryCode` | Issuer country |
| `languagePref` | `String` | Cardholder's language preference |

**`ResumeCallback` methods** (call one to drive Phase 2):

| Method | Effect |
|---|---|
| `callback.resume(OperationDto)` | Proceed with the Sale |
| `callback.finishWithoutCardOperation()` | End the session without charging — token is still issued |
| `callback.cancel()` | Cancel the operation entirely |

#### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `CARD_READ_ERROR` | Terminal failed to read the card | Ask cardholder to retry |
| `TOKENIZATION_NOT_ENABLED` | Not configured for this merchant | Contact Handpoint team |
| `DECLINED` | Issuer declined in Phase 2 | Ask cardholder for another card |
