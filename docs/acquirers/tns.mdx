## Sale

### What this does
Authorises and captures a card-present payment in a single step.

### When to use it
Use for standard retail and hospitality transactions where the cardholder is present and the amount is known before the transaction starts. Do NOT use when the final amount may change after authorisation — use Pre-Authorization instead.

### Implementation notes

1. The terminal handles EMV chip, contactless, and magnetic stripe automatically — you do not specify the card entry method.
2. The SDK returns an `OperationStartResult` synchronously with a `transactionReference`. The actual result arrives asynchronously via the events listener/callback.
3. Always store the `transactionReference` immediately — you need it for any subsequent reversal.
4. Amount is in the smallest currency unit (cents/pence). `1000` = $10.00 USD.

:::note TNS
TNS processes Interac card-present transactions only. The only post-sale operation is VOID — full amount, card must be inserted or tapped, must occur before settlement. Show VOID in your UI, not Refund. Credit refunds are not supported by Interac network. Pre-authorization is explicitly rejected (BAD_REQUEST).
:::

### Parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `amount` | integer | Yes | Amount in smallest currency unit (cents). `1000` = $10.00 |
| `currency` | string | Yes | ISO 4217 currency code. e.g. `"USD"`, `"GBP"`, `"EUR"` |
| `terminal_serial_number` | string | Yes (REST) | Target terminal. Not required for SDK paths (terminal already connected). |

### Errors

| Code | Meaning | Recovery |
|---|---|---|
| `DECLINED` | Issuer declined the card | Ask cardholder to try another card |
| `TIMEOUT` | Terminal did not respond within timeout | Check terminal connection; retry |
| `CANCELLED` | Cardholder cancelled at terminal | No action required |
| `COMMUNICATION_ERROR` | Network failure | Verify connectivity; retry |

## Void

### What this does
Voids a transaction — used for Interac card transactions where standard reversal is not available.

### When to use it
Use specifically for Interac card transactions via TNS. For non-Interac transactions, use Reversal instead. The card must be physically present at the terminal. This must occur before settlement.

### Implementation notes

1. **Interac / TNS only.** For non-Interac cards, use Reversal.
2. The card must be inserted or tapped at the terminal — card-not-present void is not supported by the Interac network.
3. Full amount only — partial voids are not supported.
4. **ISV UI note:** label this button "VOID" in your application, not "Refund" or "Reverse". This is an Interac network requirement.

:::note TNS
TNS processes Interac card-present transactions only. The only post-sale operation is VOID — full amount, card must be inserted or tapped, must occur before settlement. Show VOID in your UI, not Refund. Credit refunds are not supported by Interac network. Pre-authorization is explicitly rejected (BAD_REQUEST).
:::
