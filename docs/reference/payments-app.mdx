# Handpoint Payments App

The Handpoint Payments App is the payment software that ships on Handpoint-provisioned terminals. Two variants exist — one for **PAX SmartPOS** terminals and one for **Bluetooth mPOS** readers (HiLite / Datecs). Both share the same backend but differ in where they run and how the card reader is attached.

:::info Installation and updates
The app is distributed by Handpoint. Contact your Handpoint relationship manager for installation, updates, or to confirm which version is running on your terminals.
:::

---

### Standalone Mode

In standalone mode the terminal operates independently — no POS integration required. A cashier enters the sale amount on the terminal keypad, and the card reader collects the payment.

This is the default mode for all newly provisioned PAX terminals.

**Supported operations in standalone:**

| Operation | Available |
|---|---|
| Sale | ✓ |
| Refund | ✓ |
| Reversal (void) | ✓ |
| Pre-authorization | ✓ |
| MOTO (no card reader) | — |
| Tip adjustment | — |

### Integrated Mode (Cloud API)

Integrated mode connects the terminal to your POS software via the Handpoint Cloud. Your server sends payment commands through the REST API; the cashier no longer enters amounts on the terminal. The payment UI and card-reading flow on the terminal are otherwise identical to standalone.

**Key behavioral differences from standalone:**

- Transaction initiation comes from the POS, not the keypad
- Sale amount is sent by the POS and displayed on the terminal (keypad is locked)
- MOTO transactions and tip adjustments are available

**To enable integrated mode on the terminal:**

1. Open **Settings** in the app.
2. Toggle **Integrated Mode** on.
3. Enter the integration code provided by your Handpoint integration engineer.

:::info
Integrated mode must also be provisioned by Handpoint on the merchant account before the terminal will accept Cloud API commands. Contact your Handpoint integration engineer to enable it and obtain an API key.
:::

See the [Cloud API Integration Guide](/reference/cloud-api-integration-guide) for full API usage details.

### Kiosk & Unattended Modes

| Mode | Description |
|---|---|
| **Kiosk** | Android nav buttons disabled — prevents navigation away from the payment app. Used for customer-facing self-service kiosks. |
| **Unattended** | Fully automated mode for vending machines, parking meters, etc. Terminal shows a standby screen until a Cloud API command triggers a transaction. |

Both modes require Handpoint provisioning. Contact your Handpoint relationship manager to enable them.

The **Transactions** tab shows all transactions in the current open batch. For each entry merchants can:

- View the full transaction detail (card scheme, amount, auth code, reference number)
- Print or re-print a customer or merchant receipt
- Initiate a reversal or refund from the detail screen

Transactions accumulate in the open batch until settlement. You can close a batch manually from the app's **Batch** menu or remotely via the [Cloud API batch operations](/acquirers/epi#batching).

### Security Policy {#security-policy}

:::info Available from App 4.14.1 (Android SDK 7.1014.1)
:::

Security Policy replaces the all-or-nothing kiosk mode with four independent restrictions. Each can be enabled or disabled separately via the Cloud API `set-security-policy` command.

| Restriction | What it does |
|---|---|
| **Hide tab bar** (`hideTabBar`) | Hides the bottom navigation (Analytics, Transactions, Settings). The payment screen stays in the foreground; Android system menus (Wi-Fi, status bar) remain reachable. Use this for staff-facing checkout where you want to prevent navigation away from the payment screen without fully locking the device. |
| **Block system UI** (`blockSystemUI`) | Locks the Android status bar and navigation bar. Combined with `hideTabBar`, this is equivalent to full OS-level lockdown. |
| **Dim on idle** (`brightness`) | Dims the screen to minimum brightness during idle periods. |
| **Password to exit** (`passwordToExit`) | Requires a PIN or password to disable active restrictions. Use alongside `hideTabBar` or `blockSystemUI` to prevent merchants from disabling the policy at the terminal. |

To configure Security Policy remotely, see [`set-security-policy`](/back-office/device-commands#set-security-policy).

Settings survive app restarts and device reboots — the device synchronizes the policy from the server on start-up.

## mPOS (HiLite / Datecs) {#mpos-app}

The Handpoint mPOS app runs on the **merchant's own Android or iOS device** and connects to a portable card reader (HiLite or Datecs) over Bluetooth. It provides the same charge screen, transaction history, and analytics as the SmartPOS app.

| | SmartPOS App | mPOS App |
|---|---|---|
| Runs on | PAX SmartPOS terminal | Merchant's Android / iOS phone or tablet |
| Card reader | Built into the terminal | HiLite or Datecs over Bluetooth |
| Distribution | PAX Store (via Handpoint) | Google Play / Apple App Store |
| Integrated mode | ✓ | ✓ |
| Kiosk / Unattended | ✓ | — |

For a full hardware comparison see [HiLite vs PAX SmartPOS](/reference/hilite-vs-pax).
