Get Started page — layout approach

Three ways to structure the guided integration selector

A

Sequential wizard (Stripe-style)

One question at a time. User picks Market → Use Case → Integration Path. Each answer reveals the next step. Final step shows filtered acquirers + capabilities for that exact combination.

Pros

  • Zero cognitive overload — only one decision at a time
  • Feels guided and intentional
  • URL can be shareable/bookmarkable per path

Cons

  • More clicks to reach content
  • Returning users have to re-select
B

Single-page filter panel

All three dropdowns/chips shown on one page (Market, Use Case, Path). Results filter live below as selections change. No page transitions — ISV sees everything at once and adjusts.

Pros

  • Fastest for users who know what they want
  • Easy to compare across options
  • One page, no back-navigation

Cons

  • Busier initial render
  • Less guided — new ISVs may not know what to pick
C

Progressive disclosure (hybrid)

Large visual cards for Market at the top (Europe / US & Canada). Clicking one reveals Use Case cards below (POS Cloud / Handheld). Choosing that reveals the integration path recommendation + acquirer table — all on one scrollable page without leaving.

Pros

  • Visually engaging — mirrors Stripe's card-based design
  • No page reload, content reveals in place
  • Choices remain visible as context while reading results

Cons

  • More complex to implement (animated reveal)
  • Selections don't persist across navigation

My recommendation: C (Progressive disclosure) — most visually engaging and closest to Stripe's approach without requiring page routing. Click your preferred option, then respond in the terminal.
